## העלאה לאוויר (כשעה)

### 1 · GitHub
1. נרשמים ב-[github.com](https://github.com) → **New repository** → שם `tamara` → **Private**.
2. **uploading an existing file** → גוררים את כל תוכן התיקייה (כולל התיקיות `api`, `assets`, `scripts`, `supabase`, `.github`) → **Commit**.

### 2 · Supabase
1. [supabase.com](https://supabase.com) → **New project**. אזור: **Central EU (Frankfurt)**.
2. **SQL Editor → New query** → מדביקים את כל `supabase/schema.sql` → **Run**. (בטוח להריץ שוב בכל עדכון.)
3. מנהל: **Authentication → Users → Add user** (אימייל + סיסמה, **Auto Confirm User**), ואז ב-SQL Editor:
   ```sql
   insert into public.admins (email) values ('you@example.com');
   ```
4. **Authentication → URL Configuration**: ‏**Site URL** = כתובת האתר. ב-**Redirect URLs** מוסיפים `https://הדומיין/**` (שתי כוכביות: מכסה את הניהול, ממשק המארחים והכניסה של אורחים ל"הפניות שלי" מכל דף).
5. כניסה עם Google (לא חובה): ב-[Google Cloud Console](https://console.cloud.google.com) → **APIs & Services → Credentials → Create OAuth client ID** (Web). ב-**Authorized redirect URIs**: ‏`https://<project-ref>.supabase.co/auth/v1/callback`. את ה-Client ID וה-Secret מדביקים ב-Supabase: **Authentication → Sign In / Providers → Google**.
6. **מיילים של מערכת הכניסה (חובה):** המיילים המובנים של Supabase שולחים רק כמה מיילים בשעה ורק לחברי הצוות בפרויקט, ולכן מארחים לא יקבלו אימות או "שכחתי סיסמה" בלי SMTP משלכם. ב-**Authentication → Emails → SMTP Settings**: ‏host `smtp.resend.com`, ‏port `465`, ‏user `resend`, ‏password = מפתח ה-API של Resend, ‏Sender = `noreply@הדומיין` (מהדומיין שאימתתם ב-Resend). אחר כך ב-**Authentication → Rate Limits** מעלים את "emails per hour" (ברירת המחדל עם SMTP משלכם היא 30) ל-100 בערך.
7. **תבניות המייל בעברית:** ב-**Authentication → Emails → Templates** מעתיקים את הנושא והתוכן מהתיקייה `supabase/email-templates/` (פירוט בקובץ ה-README שם): אישור הרשמה, הזמנה, קישור כניסה, איפוס סיסמה ושינוי אימייל.
8. **הגדרות כניסה:** ב-**Authentication → Sign In / Providers → Email**: ‏**Confirm email** דלוק (כך לקוח נפתח רק אחרי אימות המייל), ‏**Minimum password length** ‏8, ‏**Password requirements**: ‏Letters and digits. בתוכנית Pro כדאי להדליק גם **Prevent use of leaked passwords**. אימות דו-שלבי (TOTP) פעיל אצל Supabase כברירת מחדל, ומפעילים אותו לכל מנהל מ"החשבון שלי" בפאנל.
9. **Project Settings → API Keys**: מעתיקים את ה-**Publishable key** (מתחיל ב-`sb_publishable_`) ואת ה-**Secret key** (מתחיל ב-`sb_secret_`, סודי!). את **Project URL** (בצורה `https://xxxx.supabase.co`) מוצאים בכפתור **Connect** בראש הדף.
   > בפרויקטים ישנים יש במקומם anon ו-service_role. גם הם עובדים, אבל Supabase מפסיקה אותם בסוף 2026, אז עדיף החדשים.

### 3 · Resend (מיילים)
1. [resend.com](https://resend.com) → **Domains → Add domain** → מוסיפים את רשומות ה-DNS אצל רשם הדומיין.
2. **API Keys → Create** → שומרים.
> עד שהדומיין מאומת אפשר לשלוח רק לאימייל שאיתו נרשמתם, מהכתובת `onboarding@resend.dev`.

### 4 · Cloudinary (לא חובה)
מ-[cloudinary.com](https://cloudinary.com) → **Settings → API Keys**: ‏Cloud name, ‏API Key, ‏API Secret.

### 5 · Vercel
1. [vercel.com](https://vercel.com) → **Add New → Project** → בוחרים את המאגר `tamara`. ‏Framework: **Other**. שאר ההגדרות נקראות מ-`vercel.json`.
2. **Environment Variables** (לפני Deploy):

| משתנה | ערך | סודי? |
|---|---|---|
| `SUPABASE_URL` | Project URL | לא |
| `SUPABASE_PUBLISHABLE_KEY` | Publishable key (`sb_publishable_…`) | לא |
| `SUPABASE_SECRET_KEY` | Secret key (`sb_secret_…`) | **כן** |
| `SITE_URL` | `https://www.tamara.co.il` | לא |
| `RESEND_API_KEY` | מ-Resend | **כן** |
| `NOTIFY_FROM` | `תמרה <noreply@tamara.co.il>` | לא |
| `ADMIN_EMAIL` | לאן יגיעו פניות (אפשר לשנות גם בהגדרות האתר) | לא |
| `CRON_SECRET` | מחרוזת אקראית ארוכה (32 תווים ומעלה) | **כן** |
| `CLOUDINARY_CLOUD_NAME` / `CLOUDINARY_API_KEY` / `CLOUDINARY_API_SECRET` | לא חובה | הסוד **כן** |
| `DEPLOY_HOOK_URL` | ראו שלב 6 | **כן** |

3. **Deploy**. הבנייה כותבת את המפתחות הציבוריים ל-`config.js` באופן אוטומטי, כך שאין צורך לערוך אותו. המפתחות הסודיים נשארים רק בשרת.
4. **Settings → Domains** → מחברים את הדומיין.

### 6 · עדכון אוטומטי של דפי גוגל
1. Vercel → **Settings → Git → Deploy Hooks** → שם `nightly`, ענף `main` → **Create** → מעתיקים את הכתובת.
2. מדביקים אותה כ-`DEPLOY_HOOK_URL` ב-Vercel (ואז **Redeploy** פעם אחת).

### 7 · GitHub Actions
ב-GitHub: **Settings → Secrets and variables → Actions → New repository secret**: ‏`SITE_URL`, ‏`CRON_SECRET` (אותו ערך כמו ב-Vercel), ‏`DEPLOY_HOOK_URL`.
לגיבוי שבועי מוצפן של מסד הנתונים מוסיפים גם `SUPABASE_DB_URL` (ב-Supabase: **Connect → Session pooler**, פורט 5432) ו-`BACKUP_PASSPHRASE` (סיסמה ארוכה שאתם שומרים גם אצלכם, בלעדיה אי אפשר לשחזר). הגיבוי נשמר 30 יום ב-**Actions → Weekly DB backup → Artifacts**, והוראות השחזור בראש הקובץ `.github/workflows/backup.yml`.
מעכשיו: סנכרון יומנים כל שעה, בנייה מחדש של דפי גוגל כל לילה וגיבוי כל שבוע. בלשונית **Actions** אפשר להריץ ידנית ולראות תוצאות.

### 8 · גוגל
[Google Search Console](https://search.google.com/search-console) → מוסיפים את הדומיין → **Sitemaps** → `sitemap.xml`.

### 9 · בדיקה אחרי העלאה
- בפאנל הניהול: **בדיקת מערכת**. היא בודקת את הטבלאות, ההרשאות ומשתני הסביבה ב-Vercel, ואומרת מה חסר ואיך מתקנים.
- **הגדרות → מיילים אוטומטיים → שליחת מייל בדיקה אליי**, ו"מה יישלח היום?" (תצוגה מקדימה של המשימה היומית).
- הרשמה כמארח מ"פרסום מתחם" עם אימייל אמיתי → מגיע מייל אימות בעברית → אחרי הלחיצה נפתח ממשק המארחים עם "מעלים את המתחם לאוויר", והלקוח מופיע ב**לקוחות**.
- **שכחתי סיסמה** בכניסת המארחים ובכניסה לניהול → מגיע קישור → בוחרים סיסמה חדשה.
- שולחים פנייה מדף מתחם → מגיע מייל למנהל, למארח ואישור לאורח.
- בעורך מתחם: **סנכרון עכשיו**, ופתיחת קישור הייצוא (קובץ ‎.ics).
- העלאת תמונה מהעורך.
- פתיחת `/zimmer/<מזהה>/`, ‏`/l/golan/`, ‏`/s/<יישוב>/` ו-`/sitemap.xml`.
- הרשמה לדיוור מעמוד הבית → מגיע מייל אישור → אחרי הלחיצה המנוי מופיע ב**מנויי דיוור** כ"מאושר".

### מעבר מההדגמה (לא חובה)
בהדגמה: **הגדרות האתר → ייצוא → העתקה**. באתר המחובר: **הגדרות האתר** → מדביקים → **ייבוא מהתיבה**. מתחמי הדוגמה לא עוברים, ותמונות שהועלו בהדגמה צריך להעלות מחדש.

## עבודה שוטפת

**אחרי כל עדכון של האתר מהמאגר:** מריצים שוב את `supabase/schema.sql` ב-SQL Editor של Supabase (בטוח, לא מוחק נתונים). אם שוכחים, פס צהוב בראש פאנל הניהול מזכיר, ו**בדיקת מערכת** מראה מה חסר.

**מארח חדש (הרשמה עצמית):** ב"פרסום מתחם" ממלא שם, טלפון, אימייל, שם המתחם, יישוב, אזור, סוג, יחידות, ח.פ (לא חובה), סיסמה ואישור תנאי הפרסום → מקבל מייל אימות → רק אחרי הלחיצה נפתח לו לקוח בתקופת ניסיון (ברירת מחדל 30 יום) ומתחם מוסתר, ומגיע מייל "ברוכים הבאים" אליו ועדכון אליכם. במסך הבית שלו רשימת "מה חסר" (5 תמונות, תיאור, מחיר, טלפון) וכפתור **שליחה לבדיקה ופרסום** → מייל אליכם, ובקשה ב**אישורי תוכן** → **אישור והצגה באתר** מפעיל את המתחם ושולח לו "המתחם באוויר". רוצים לאשר כל הרשמה בעצמכם? **הגדרות → מארחים חדשים** → מכבים "פתיחה אוטומטית", וההרשמות מחכות ב**בקשות הצטרפות**. מי שמעדיף שתחזרו אליו בוחר בטופס "מעדיפים שנחזור אליכם" (בלי סיסמה).

**לקוח שאתם מוסיפים:** **לקוחות → לקוח חדש** עם אימייל → הלקוח מקבל מייל הזמנה לבחירת סיסמה. בכרטיס הלקוח: שליחה חוזרת של ההזמנה, או **קישור כניסה לוואטסאפ** כשהמייל לא מגיע.

**כניסת מארח:** אימייל וסיסמה (או קישור חד-פעמי למייל). "שכחתי סיסמה" שולח קישור לבחירת סיסמה חדשה. הוא רואה רק את המתחמים שלו ולא יכול להפעיל, לקדם, לשנות סנכרון או להאריך מנוי. ב**החשבון שלי** הוא מעדכן טלפון, כתובת וח.פ לחשבוניות, בוחר אילו מיילים לקבל, מחליף סיסמה ומתנתק מכל המכשירים.

**כרטיס לקוח:** לוחצים על שם הלקוח ב**לקוחות**. מנוי ומצב התצוגה באתר, הארכה בחודש או בשנה, השהיה וסיום, רישום תשלומים (חודש, סכום, אמצעי, מספר קבלה), המתחמים, פניות אחרונות, מצב הכניסה לממשק (הוזמן / אומת / נכנס לאחרונה), ויומן כל השינויים בלקוח ובמתחמים שלו. ברשימה יש סינון: מוצגים, מסתיימים ב-30 יום, בניסיון, הסתיימו, ביקשו חידוש.

**מנויים ותצוגה באתר:** המתחמים של לקוח מוצגים לגולשים רק כשהלקוח פעיל או בניסיון, והמנוי בתוקף. אחרי תאריך הסיום יש ימי חסד (ברירת מחדל 3), ואז המתחמים מוסתרים אוטומטית (גם מהחיפוש, מדפי המתחם ומדפי גוגל), בלי למחוק כלום. הארכה מחזירה אותם מיד. ללקוח נשלחות תזכורות לפני הסיום (ברירת מחדל 30, 7 ויום אחד לפני), הודעה ביום הסיום והודעה כשהמתחם הוסתר. בממשק שלו הוא רואה עד מתי המנוי בתוקף ולוחץ **בקשת חידוש** → מייל אליכם וסימון ברשימת הלקוחות. הכל ניתן לשינוי ב**הגדרות → מארחים חדשים ומנויים**.

**מיילים אוטומטיים:** אישור לאורח על בקשה, בקשת חוות דעת יום אחרי העזיבה (להזמנות שסומנו "נסגרה"), סיכום יומי אליכם, ומיילים למארח כשהשינויים אושרו או נדחו (עם הסיבה) וכשחוות דעת פורסמה. כל מייל אוטומטי נשלח פעם אחת בלבד, גם אם המשימה רצה שוב. מדליקים ומכבים ב**הגדרות → מיילים אוטומטיים**.

**אבטחה:** אימות דו-שלבי למנהלים (**החשבון שלי** → סורקים QR באפליקציית אימות). מנהל שהפעיל אותו מקבל הרשאות במסד הנתונים רק אחרי הקוד, גם אם הסיסמה דלפה. ב**צוות הניהול** מוסיפים ומסירים מנהלים (מנהל חדש מקבל מייל לבחירת סיסמה). הגנה מהצפה בטפסים (יותר מ-5 פניות מאותו טלפון ב-10 דקות נחסמות), שדה נסתר נגד רובוטים, ויומן פעולות של כל שינוי בלקוחות, מתחמים, בקשות, הגדרות וצוות.

**אישור שינויים:** כשהאפשרות פעילה (הגדרות), שינוי של מארח בשם, תיאור, תמונות, מאפיינים, סרטון או תוכן הדף (נושאים, כלול באירוח, חוקי הבית, שאלות) ממתין ב**אישורי תוכן** עם השוואה לפני/אחרי. מחירים, יומן, יחידות ומדיניות מתעדכנים מיד.

**עורך המתחם:** פס קפיצה בראש העורך, ו"שלמות הכרטיס" בצד מראה מה עוד חסר (תמונות, תוכן, מדיניות, מיקום). לכל תמונה בוחרים קטגוריה (פנים, חדר שינה, ספא, בריכה, נוף, אוכל) והיא מסננת את הגלריה באתר.

**יחידות במתחם:** בעורך, "כמה יחידות" → לכל יחידה מחיר, מחיר מ־2 לילות, תפוסה, מיטות, חדרי רחצה, גודל, תיאור, מאפיינים, תמונות, יומן וקישור iCal משלה. האורח יכול להזמין כמה יחידות באותה בקשה.

**תמחור:** אמצע שבוע / סופ"ש (לילות חמישי ושישי) / חג, מחיר מוזל משני לילות, עונות באחוזים ועם מינימום לילות, מינימום לילות לסופ"ש ולחג, תוספת למבוגר ולילד מעבר לבסיס, חבילות (לינה וארוחת בוקר וכו'), תוספות בתשלום (או "בתיאום"), הטבות באחוזים לקהלים, קופונים ו"דקה 90" (הנחה אוטומטית על סופ"ש הקרוב אם פנוי). החגים מחושבים מראש ל-2027–2028 וניתנים לעריכה.

**מדיניות:** שעות כניסה ויציאה (גם בשבת), ילדים, עישון, "לזוגות בלבד", מדרגות ביטול (עם תבניות מוכנות) וחוקי הבית. כל אלה מופיעים בדף המתחם ונכנסים אוטומטית לשאלות הנפוצות ולגוגל.

**פניות:** ארבעה סוגים: בקשת הזמנה, "מצא לי צימר", יצירת קשר ודיווח על מידע שגוי. בבקשת "מצא לי צימר" המערכת מציעה מתחמים פנויים שמתאימים, ואפשר לשלוח אותם לאורח בוואטסאפ בלחיצה. **ייצוא CSV** פותח את כל הפניות באקסל.

**מה עושים באזור:** מוסיפים מסעדות, אטרקציות, ספא, יקבים ומסלולים עם קואורדינטות. הם מופיעים בעמוד "מה עושים באזור" ובדף של כל מתחם במרחק עד 30 ק"מ, עם ניווט ב-Waze.

**דיוור:** הרשמה בהסכמה כפולה: מי שנרשם מקבל מייל ולוחץ לאישור, ורק אז מופיע כ"מאושר" ב**מנויי דיוור**. "העתקת מאושרים" ו-CSV כוללים רק מאושרים, וב-CSV יש לכל מנוי קישור הסרה אישי להדבקה בכלי הדיוור. לפי חוק התקשורת (סעיף 30א): שולחים רק למאושרים, כותבים "פרסומת" בתחילת הנושא, ומצרפים קישור הסרה. הרשמות שלא אושרו נמחקות אחרי 30 יום.

**עמוד הבית:** ב**הגדרות** יוצרים "אוספים" (למשל "לירח דבש") ובוחרים להם מתחמים, מדליקים או מכבים את "מצא לי צימר", כפתור הוואטסאפ הצף והודעת העוגיות, ומוסיפים קישורים לרשתות החברתיות.

**iCal:** מדביקים בעורך את קישור הייצוא מ-Booking/Airbnb, והתאריכים שלהם נחסמים כאן (כל שעה). את קישור הייצוא שלנו מדביקים אצלם. מיוצאים רק תאריכים שסומנו כאן, כדי לא ליצור לולאה.

**חוות דעת מאומתות:** בפניות, מסמנים פנייה כ"נסגרה" → **בקשת חוות דעת** → שולחים לאורח את הקישור האישי (חד־פעמי) בוואטסאפ או במייל. אם האורח השאיר מייל, הבקשה נשלחת גם אוטומטית יום אחרי העזיבה. החוות דעת ממתינה לאישורכם, והמארח מקבל מייל כשהיא מתפרסמת ויכול להגיב.

**חיובים:** בכרטיס הלקוח בוחרים מודל: מנוי, תשלום לפי פנייה, או שניהם. במסך **חיובים** רואים כמה כל אחד חייב החודש ומסמנים ששולם, ובכרטיס הלקוח רושמים כל תשלום עם אמצעי ומספר קבלה. הגבייה עצמה ידנית.

**תמונות:** מתמונה שמעלים נוצרים שני גדלים בדפדפן (2000 פיקסלים לגלריה ו-800 לכרטיסים), והם נשמרים ב-Supabase Storage (או ב-Cloudinary, אם הוגדר). **הגדרות → תחזוקת תמונות** מוחק תמונות שהועלו ולא נשמרו באף מקום.

**קידום:** "נבחרי העונה" (כוכב) ו"ממומן עד" (תאריך) מופיעים בראש העמודים והחיפוש.

**דפי גוגל:** נבנים כל לילה: דף לכל מתחם (עם שאלות נפוצות ונתונים מובנים), לכל אזור, אזור + מאפיין ("צימרים עם ג'קוזי ברמת הגולן"), אזור + סוג ("וילות בגליל העליון"), צפון/מרכז/דרום, סוג אירוח, יישוב (`/s/ein-hod/`), מה עושים באזור, ודפי נחיתה (דילים, דקה 90, פנויים לסופ"ש, המומלצים, מצא לי צימר, מגזין). אחרי שינוי גדול: **הגדרות האתר → עדכון דפי גוגל ומפת האתר עכשיו**.

## לפני שמפרסמים

- **משפטי:** הצהרת הנגישות, תנאי השימוש, מדיניות הפרטיות ותנאי הפרסום למארחים (`#terms-hosts`) הם נוסח בסיסי. כדאי שעורך דין ויועץ נגישות יעברו עליהם (כולל חוק הגנת הפרטיות ותיקון 13), וימלאו את פרטי רכז/ת הנגישות. כשמשנים את תנאי הפרסום, מעלים את `T.HOST_TERMS_VERSION` ב-`assets/js/core.js` (הגרסה נשמרת עם כל הרשמה).
- **מספר טלפון וירטואלי למארחים** (כדי למדוד שיחות ולהסתיר את המספר האמיתי) דורש ספק טלפוניה בתשלום. כרגע נמדדות לחיצות "הצגת טלפון" ו"וואטסאפ".
- **מה לא נבנה בכוונה:** גרסה באנגלית, צ'אט בינה מלאכותית, חדרים לפי שעה, תיבת הודעות בין אורח למארח בתוך האתר (הפנייה עוברת לוואטסאפ/מייל), אימות SMS ותמונות בחוות דעת של אורחים. כל אחד מהם דורש שירות בתשלום או תחזוקה שוטפת, ואפשר להוסיף בהמשך.
- **סליקה:** אין גבייה אוטומטית. החיובים מחושבים באתר והגבייה נעשית בנפרד.
